# 需求分级

优先遵守目标仓当前规则；未规定时按行为风险判断，不单按文件数升级流程。

| 级别 | 判定 | 分析交付 |
| --- | --- | --- |
| 小修 | 现有行为的局部缺陷或小调整，改什么和为什么可一句话说清，无新接口及产品决策 | 原因、最小建议、受影响行为与验证方法 |
| 中等 | 需要协调若干路径，目标与边界已明确 | 一份范围清楚的实施计划和验收条件 |
| 大需求 | 新能力、跨模块契约、产品取舍尚未确定 | 明确目标与非目标、待定决策，再收敛方案 |

例：按钮重复点击产生重复请求，暂定小修；后续发现前后端幂等协议不一致则重估。会话中出现“BUG”不代表一定小修。

这三档只决定交付深度。“小修可直接改”仅在实施能力和用户授权均已具备时适用；分析任务不因此变成写任务。团队源文档始终只读，自有台账的进度由 Agent 在授权范围内更新。
