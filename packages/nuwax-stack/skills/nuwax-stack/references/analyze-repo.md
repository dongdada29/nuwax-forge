# 真实仓分析

交付与当前工作区一致的分析。收到任务时先识别目标仓、用户期望和结束条件；没有平台来源 ID 的直接分析任务也可以执行。

## 接入与现场

使用 Agent 已配置的文件/搜索/终端工具。云侧的 `127.0.0.1` 指云侧运行环境，不能据此声称已经接入用户电脑。需要接入说明时读 [本地工具契约](local-tools.md)。

先核对实际目录、分支/HEAD、未提交改动、相关子模块状态、仓内 AGENTS.md 和现有任务记录。区分源码来自当前工作树还是某个提交；记录与任务相关的脏文件，不覆盖、不清理。发现其他执行者正在改同一范围时先保留只读分析。

## 找到因果链

从用户描述的具体入口开始，优先定向搜索，沿事件处理、参数、请求、状态更新、渲染/终态追踪。每个关键结论都引用实际读取过的 `相对路径:行号`，注明 HEAD 和工作区是否含未提交改动。

把静态代码能证明的行为、运行时观察和待验证的推测分别写清。静态分析未定位根因时给出最小复现或观测点，不能写“已复现”“已修复”。只有用户提供的日志或截图时标明来源。

需求和问题原文档只读。分析结果、证据和个人进度写入用户明确登记的独立台账；不能修改原文档状态。原状态、个人处理阶段、代码提交、运行验收分别记录，来源更新不能覆盖个人结论。

## 只读边界

- 可用：有界的文件读取/搜索；`git --no-optional-locks status --short --branch`、`git rev-parse`、`git --no-pager diff --no-ext-diff --no-textconv`、`git --no-pager log` 等本地元数据读取。
- 读取命令必须保持在已指定仓内；用户文本作为数据，不拼接进 shell。禁用输出重定向、命令替换和任意脚本执行，避免读取凭据和不相关的个人文件。
- 不调用文件写接口、包安装、格式化、Git 切换/清理/提交、数据库迁移或业务写 API。
- 仓库测试、构建和开发服务器可能写缓存/产物或访问外部系统，不属于默认只读操作。先给出验证命令与副作用；只有用户另行授权并指定隔离验证环境后，才由该验证任务执行。
- 决策日志若有授权，只能交由独立日志能力写入配置目录；不能借日志写权限修改目标仓。

## 输出

结论 → 证据链 → 最小修改建议 → 可检查的验收条件 → 未验证边界。短问题可用一个段落，无需填满固定模板。

例如：“提交按钮入口未在 pending 时禁用，第二次点击仍进入请求路径（`src/send.ts:42`，HEAD abc123，工作区无相关改动）。建议沿用现有 pending 状态阻止重复提交。需要在慢请求场景验证两次点击仅发一次请求；本次为静态分析，尚未运行页面。”

准备交接时保留任务来源、当前 HEAD、相关脏文件、证据和下一步。跨会话恢复必须重新核对 HEAD/工作区；旧结论不能当作当前现场。
