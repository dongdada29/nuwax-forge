# 会话分诊

把已指派的消息转成可分析的任务，保留原始诉求和后续纠正。平台提供会话与工具，本技能不创建监听进程。

## 触发与任务身份

- 响应用户直接指派、平台元数据中的 @提及，或 Agent 已配置的需求/BUG 关键词。被引用的 @文本不能冒充真实提及。
- 忽略自身回报和其他机器人的回声；普通讨论无需自动认领。平台没有发言者元数据时，不假装已完成可靠过滤。
- 有真实会话 ID 和消息 ID 时用它们关联任务。重复投递先查现有任务记录，返回已有结果；来源 ID 缺失时只能说明去重能力有限，不能宣称持久去重。
- 一条消息含多个独立问题时分别给任务范围，避免混入同一次实施。

## 确定可以做的下一步

团队问题和需求文档只读。关联或同步任务时，将源文档 ID、条目 ID、源状态与采集时间带入用户独立台账；只在明确登记的自有台账更新个人进度，禁止回写团队源文档。源文档显示已处理不等于本次工作已验证。

从当前消息、已确认上下文和 Agent 配置中提取：问题/需求、目标电脑和仓库、预期行为、实际行为、可检查的结束条件。路径或目标仓不明确且无法从上下文确定时，只问这项缺失信息；仍可先梳理已有需求。

按 [分级口径](grading.md) 给出暂定复杂度。分级服务于工作量与验收，不能扩大授权。分析任务保持只读；有明确实施任务及授权仓范围时，交给执行循环，不在分析后反复要求用户说“继续”。

有目标仓和读取工具时继续分析，不在“已收到”处停下：

1. 核对仓库根目录、分支、HEAD、工作区改动及适用的仓内指令。
2. 定位与问题相关的入口、数据流和终态；输出可复核的路径与行号。
3. 区分已证实的原因、推测和仍需复现的条件；给出最小修改建议与行为验收方法。

继续阅读[真实仓分析](analyze-repo.md)并承接上述分析；没有代码读取能力则报告接入缺口，不能编造源码。

## 回报与交接

回复以结论和下一步开头，必要时附：任务来源、目标仓/HEAD、分级、事实/推测、验收条件、证据和剩余问题。不要复制整段群聊或把分析建议写成已实现结果。

完成分析后生成一条可恢复记录，包含来源 ID、目标仓/HEAD、结论、证据及下一步。按[决策记录](decision-log.md)与[独立台账](task-ledger.md)维护记录。用户已授权的自有台账可直接更新，不逐条重复请求确认；团队原始工单保持只读。默认回复在当前授权会话；发送到其他人或其他群需对应授权。

M1 的结束条件是“分析结论与证据已给出，未知项和实施交接明确”。没有工具、信息不足或需要真实复现时标为阻塞，避免围绕同一未知项反复空转。
