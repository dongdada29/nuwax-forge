# 独立工作台账

用户拥有自己的工作文档。团队原始文档是只读来源；所有个人状态变化只写配置中明确登记的自有文档。账号拥有编辑权限不代表可写源文档。

## 读写范围

执行写操作前，核对当前平台 origin、自有文档 ID、来源文档 ID 列表。未配置自有 ID、ID 与来源重叠、目标不是登记的自有文档时停止该写入。不要通过复制链接、另存、评论或文档内嵌对象绕过边界。工具层应仅暴露对自有 ID 的写能力；本技能文本不是平台 ACL 的替代品。

不得回写来源状态、负责人、备注、评论或删除标记。用户以后用个人台账与同事对接；把源表改成“完成”不是本任务的结束条件。

## 同步与进度

用 `(来源页面ID, 来源条目ID)` 关联同一个问题，保留原链接、源状态、读取时间和来源版本。只有标题相同但 ID 不同的条目先标记疑似重复，不能自动合并。

源字段与个人字段分开：来源同步仅更新原文标题/状态/快照；个人阶段、实现证据、验收证据、阻塞原因和备注保留。源条目消失或撤回时标记待核对，不删除自己的工作记录。文档不可达时显示上次采集时间与同步失败，不把旧快照当实时结果。

个人阶段使用待分析、分析中、实施中、验证中、待决策、受阻、待验收、已完成。代码存在、提交、测试、安装包、上线分别记录；只有已满足任务的可检查完成条件，才标个人已完成。

首次接手先盘点存量：线上条目 → 本机已有清单 → 相关分支/提交/未提交工作 → 已有验证证据。不要重做已完成工作，也不能仅凭旧会话“已修复”认定当前完成。

## 本地合并助手

读 [scripts/ledger.py](../scripts/ledger.py) 了解本地状态格式。脚本只合并本地记录、校验文档写目标并渲染 Markdown，不连接平台。平台写入工具必须另外执行相同 ID 检查，并使用已核实的版本/修订机制避免覆盖用户并发编辑。

每次同步或状态变更保留事件记录。向群里回报时用 Agent 自己的身份，附自有台账条目链接及证据；是否发群消息仍以当前任务授权为准。
