# 平台 Agent 配置

1. 用 `python3 -B scripts/sync_platform.py --dry-run` 生成一个 `dist/nuwax-stack.zip`；入口为 `skills/nuwax-stack/SKILL.md`。导入或同步方式见 [平台同步](platform-sync.md)。
2. 在目标平台专用 Agent 只绑定 `nuwax-stack` 一个技能。具体 Agent ID、会话模式和当前账号权限需要在真实环境确认，本项目不假设平台有“技能组 JSON 一键导入”接口。
3. 从 [上下文样例](../config/agent-context.example.json) 填入真实电脑、仓库根目录、已暴露的读取工具。`verificationCommand` 仅记录验证入口，不赋予运行权限。
4. 首次联调保持 `mode=analysis-only`。明确任务授权、目标仓、可执行工具和隔离环境后再开启自主实施。配置源文档 ID 与自有台账 ID；团队源文档始终只读，自有台账可按用户授权直接更新。
5. 按团队已有方式把 Agent 加入目标会话。在会话发一次明确的分析指派，确认它能读到所选本机仓的真实 HEAD，并带路径/行号回报。

建议的 Agent 上下文：

> 你是罗东的研发助理。接手已指派需求和 BUG，先核对真实文档、电脑、仓库和已有进度。分析任务只读；明确实施授权后，在范围内自主循环到可检查完成条件，无需逐轮请求“继续”。团队源文档始终只读，只更新登记的自有台账。源状态、个人阶段和验证证据分开保存。关键决策可按用户授权私信罗东，其余可逆工作继续推进。没有真实唤醒或执行能力时报告缺口，不能宣称后台已运行。

验收至少覆盖：明确 @与普通引用不同；自身回报不再次触发；重复消息不重复落同一事件；目标仓不可达时不编造代码；会话中普通“确认”不越权写入；不能读取密钥；真实需求可给出完整代码因果与未知项。

本地 ZIP 结构通过不等于平台识别成功。需另外确认导入后的技能内容、Agent 实际加载、云侧工具可达和会话响应。这些结果记录到对应环境的验收材料。
