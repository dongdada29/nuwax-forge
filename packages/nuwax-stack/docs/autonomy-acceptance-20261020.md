## 通知与运行边界

按用户授权发送了一条本人决策消息，平台业务码成功且回读可见；浏览器生产回读发现 senderId 为用户本人、senderType=1，消息进入用户自聊，而非新 Agent 单聊。因此只能确认消息落库，不能报告 Agent 主动通知成功。没有发给他人或群。

已将“发送前核实 Agent 身份，发送后核对 senderId/senderType/收件会话”的规则写入决策技能 0.2.1 与 Agent 开发态系统提示，并禁止使用这条未验收路径自动代发。决策技能已重新发布并导出核对。Agent 的发布申请仍需完成审核；配置文字不等于平台权限闸门。

平台定时能力已通过有界探针：开启新 Agent 的 `openScheduledTask=Open` 后创建定时会话 `1741331`，平台自动于 09:27 启动模型。助手实际用 Python SQLite 只读查询既有任务，返回 revision=2、phase=done 和唯一标记 `awake-33302412-20261020`；会话状态为 COMPLETE。随后调用取消并回读确认 CANCEL，没有留下持续轮询任务。

该环境接受六字段 cron；七字段带年份表达式被明确拒绝，没有创建任务。有效探针按指定日月时间运行后立即取消。真实任务的定期同步周期、检查点与唤醒句柄关联、沙箱离线恢复仍待接入，不能将探针通过视为无人值守服务已上线。

本机 CLI 只保存测试域账号；生产可选电脑列表只有云端电脑。本轮未切换账号、停止测试网关或猜测凭据。需要通过正式生产电脑登录把本机通道接回，再从 Agent 读取真实仓 HEAD 验收。

## 与 pstack 的能力对照

| 能力 | 当前实现及证据 | 尚缺 |
| --- | --- | --- |
| 任务分诊与代码分析 | 技能已发布；个人台账已同步来源和当前提交线索 | Agent 经平台读取本机实际仓 |
| 完成条件与实施验证循环 | 隔离任务实际执行；保留原测试并修复失败 | 真实业务需求闭环 |
| 检查点与 session pickup | 两个生产会话恢复同一数据库并完成任务 | 沙箱重启后持久性与长期运行 |
| 原文档保护 | 来源只读；模型实际运行守卫并精确追加个人台账；浏览器回读保留原表 | 守卫是本项目助手校验，不能冒充平台 ACL |
| 独立唤醒 | 平台自动启动模型并读到检查点；探针已取消 | 持续任务策略与恢复联动 |
| 群内接单 | 已定位平台模式：@Agent 或全消息监听 | @罗东 的定向转交；尚未将新 Agent 加群 |
| 关键决策通知 | 本人自聊落库，已识别身份问题 | 以 Agent 身份投递及通知验证 |

不按技能数量给“完成百分比”：云端最小闭环已经实测，面向日常工作的完整接管尚未完成。
