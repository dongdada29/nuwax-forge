# 自主研发代理的验收目标

用户于 2026-10-20 明确：专用 Agent 最终进入第二空间全员群，承接 @罗东 的任务；关联线上需求/问题文档和本机已有进度，独立推进，关键决策私信用户。团队原文档只读，个人工作记录写入独立台账。

## 对照 pstack

参考 [自主循环](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/autonomous-run.md) 和 [断点接手](https://github.com/cursor/plugins/blob/main/pstack/skills/poteto-mode/playbooks/session-pickup.md)：可检查的完成条件、按证据逐轮推进与验证、真实唤醒机制、每轮检查点、跨会话恢复。

技能定义规则，宿主提供执行、事件和唤醒。pstack 借用 Cursor 内置 `/loop`；本项目应复用平台能力，不新增独立 daemon。没有实际调度 ID 和运行证据，不能宣称自主后台已经运行。

## 独立文档边界

源页面为十月规划及两张问题表，只读获取。新建用户自己的研发工作台账；通过源页面 ID 和条目 ID 关联，保留读取时间。

源状态与个人阶段分开。来源同步不覆盖个人进度、备注与证据。个人阶段“已完成”必须对应任务完成条件及验证证据；与团队对接时由用户提供自己的台账，不自动改原问题状态。

写入必须检查目标 origin 与自有文档 ID，不可仅依据“当前账号可编辑”。配置样例是声明，实际平台工具还须落实这一边界。

## 完整验收

1. 已有任务或明确指派能进入独立台账，同一来源重投不重复建任务。
2. 真实仓、文档与已有提交能够重建当前进度，不重复处理已完成工作。
3. 一次明确任务授权后，Agent 自动完成计划、实施、行为验证和失败修正。
4. 每轮保存状态；中断后新会话可从同一恢复点继续。
5. 外部等待有真实回调或调度句柄；没有句柄时显示待接入，不假装持续运行。
6. 关键决策私信用户，其余可逆步骤持续推进；不把每轮“继续”当必要审批。
7. 源文档在整个过程中不被写入；所有个人状态和证据只更新自有台账。

## 尚需实际接通的环节

当前 IM 契约只提供 @Agent 唤起或全消息监听；@罗东 的定向投递需要实测或平台规则，不能只靠技能文本宣称已支持。已有模型/电脑/仓库的读取与执行权限也要单独验证。

上线分层记录：技能发布、Agent 绑定、源资料同步、真实任务执行、跨会话恢复、唤醒调度和群内触发。任一层未验收就标明，不以另一层成功代替。
