01 / INSTALL

一行装 kit，一行初始化项目

所有渠道装的是同一份东西；装完 nuwa-sdlc 命令即可用。重复执行 init/check 幂等，不用重装。

① Nuwax S3 一键装（推荐）
免克隆仓库、零配置。拉 latest.json → 下载 tar.gz → sha256 校验 → 装到 ~/.nuwa-sdlc-kit/<版本>/ → 软链 ~/.local/bin/nuwa-sdlc（确认其在 PATH 里）。
$ curl -fsSLk https://s3.nuwax.com:9443/nuwax-packages/agent-engines/nuwa-sdlc-kit/install.sh | bash
② npx 直装（免装 kit）
npm 已发包，tag v* 自动发布；适合只想播种单个项目、不装全局命令的场景。
$ npx --yes @nuwax-ai/nuwa-sdlc-kit init --dir <目标仓> --name myrepo --test 'pnpm test'
③ 本仓直用
改完引擎想立刻试：直接以 node 跑 cli.mjs，旗标与装完的命令完全一致。
$ node /path/to/nuwa-sdlc-kit/cli.mjs init --dir <目标仓> --name myrepo --test 'pnpm test'
初始化（装完 kit 后，项目维度）
--profile slim|full 安装面档位（新仓默认 slim 地板档，老仓无字段视为 full）· --src plan-gate 源码区正则（仅 full，逗号分隔）· --test 全量测试命令 · --env-prefix 停用开关前缀 · --protected 受保护写入路径 · --grill 本仓特有拷问项 · --pre-commit 顺带装秘钥地板 · --ci 挑 CI 模板（github/gitlab/both，默认按 origin 自动识别）。
$ nuwa-sdlc init --name nuwax --src 'src/' --test 'pnpm exec vitest run' --env-prefix NUWACLAW --grill ./grill-extra.md

已有项目升级：新版本发布后重跑 ① + nuwa-sdlc upgrade --dir <仓> 即可全量跟平（只刷引擎件，内容件不动）；nuwa-sdlc check --dir <仓> 做分档体检（按 .sdlc.json profile），exit 1 = 有漂移。

02 / MODEL

三层内容观——升级语义的根

哪些文件 kit 替你管、哪些归仓库自己演化，边界画死。差异全部走 .sdlc.json 运行时配置，引擎文件跨仓逐字节相同。

ENGINE · 引器件

kit 托管，upgrade 覆盖

slim：guard-paths.mjs · deploy-gate.mjs；full 另含 plan-gate.mjs · sdlc-evals.mjs；含 .claude/settings.json / .zcode/config.json 合并项。

upgrade 只刷这一层——跨仓行为一致，出问题一处修处处生效。
CONTENT · 内容件

播种一次，本地所有

full：templates/ 三件 · skills 双落点 · REVIEW.md（五遍清单） · verifier.md · samples/ · CI workflow；slim 只播单件 plan 模板 + 单遍 REVIEW.md。

安装器永不覆盖——仓库自行演化，是你的文档与流程资产。
ENTRY · 入口层

托管区间，两头相安

AGENTS.md 的 nuwa-sdlc-kit:begin/end 注释对内由 kit 管理。

只替换区间内内容，区间外归仓库。
03 / GUARDS

门禁不商量，分带处理

hooks 在 PreToolUse 拦截：秘钥不落地、没计划不动手、发布类命令按带放行。停用走显式环境变量，留痕可审计。

guard-paths

BLOCK

秘钥与受保护路径护栏：检测到密钥写入即拦；--protected 声明的文件进受保护清单。

plan-gate

ASK

full 档专属：源码区（--src 正则）改动前必须有进行中的计划；slim 仓不装本闸门。临时放行：<PREFIX>_SKIP_PLAN_GATE=1。

deploy-gate

3 BANDS

发布类命令分带：block（force push 硬禁）/ ask（人工 SDLC_APPROVE_DEPLOY=1 批准）/ allow（默认带开洞）。带表在 .sdlc.json 配置。

pre-commit

FLOOR

git pre-commit 秘钥地板——agent 无关的强制层，init --pre-commit 直装 .git/hooks/。

sdlc-evals

CI

full 档 CI 门禁：对已装 hooks 灌样本事件断言 exit code，11 条用例覆盖三道闸门；规则文件变更时自动触发（GitHub workflow / GitLab CI 模板按远端挑选）。

acp-gate

PLATFORM

ACP 层参考实现：nuwa-cli serve 读工作区 .sdlc.json，对 session/request_permission 做 deny/ask——serve 托管的所有引擎统一生效；slim 仓 .sdlc.json 不写 srcPaths，计划 ask 天然静默，只保留秘钥/发布拦截。

04 / AGENTS

多 agent 兼容，三档保底

不绑死任何一个引擎：正文是通用 markdown，逐工具的能力差异显式承认，硬约束下沉到 agent 碰不到的层。

通用层

AGENTS.md / templates / REVIEW.md / skills 正文全是 markdown——codex、opencode、cursor 等直接读；skills 双落点 .claude/skills/ + .agents/skills/，ZCode workspace 级原生自动发现。

逐工具适配

PreToolUse hooks 在 Claude Code（.claude/settings.json）与 ZCode（.zcode/config.json，v1.5.0 起合入）都强制执行；verifier 的等价物 = 跑测试命令按格式贴结论。

地板层

非协商护栏下沉 git pre-commit / CI / ACP 网关——agent 无关的强制点，谁开车都翻不过去。
