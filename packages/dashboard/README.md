# Nuwax Forge Dashboard

`forge_dashboard/` 为本地服务、数据适配和页面渲染；`web/` 为样式与交互脚本。由 `nuwax-forge dashboard` 启动，服务仅绑定 loopback。Crew 保留任务路由和审批账本；适配器读取显式提供的数据源。未来桌面容器可复用本地服务与 Web 客户端。

静态 HTML 输出保留自包含样式；服务模式加载同包 Web 脚本。当前没有 Electron 客户端。

## 任务工作台

服务模式默认进入任务工作台。Crew 台账、Stack 任务与 Assignment、任务矩阵和审批记录按各自来源中的明确任务 ID 展示；同名跨来源记录不会自动合并。尚未派工的 Stack 任务也可见。无 `attemptId` 的观察单列，执行完成显示待验收，来源的完成状态不会被看板改写。

可搜索任务、目标和尝试 ID，并按阶段、来源、执行器、最近事件时间筛选。筛选、工作台页码和任务详情保存在页面 URL，刷新后保持；详情包含目标、验收条件、审批摘要、执行与交付、分来源用量和事件时间线。原始执行表和来源矩阵保留在派工流水页。静态 HTML 用原生折叠详情阅读，不加载交互脚本。

来源面板区分未接入、文件缺失、已读取与记录较旧。超过 15 分钟的运行来源记录标记较旧，注册表、任务矩阵、审批等静态来源不按心跳判断。页面读取时间、文件更新时间和事件时间是不同口径，均不证明执行进程存活。

`workbench.py` 是只读展示投影，`task_views.py` 负责 HTML，`web/` 负责交互。这里的筛选阶段不是新的持久任务状态机；不新增任务库、审批门或执行引擎。personal-agent 的成果接收与 Forge 的执行观测保持各自现有语义，未来消费公共插件/验证结果契约时通过适配器接入。

## 扩展和 DSH

内建来源通过 `forge_dashboard.adapters.AdapterRegistry` 显式注册；调用方可注册读取器返回统一记录，不会自动搜索或执行外部插件。DSH 插件依赖 Cordis 和 DSH 的服务，应由真正的 DSH 宿主运行，不能直接当成 Python 适配器。Forge 的 `dsh-plugin` 命令将插件管理和运行委托给已安装的 DSH，插件界面仍在 DSH 中，尚未嵌入 Forge 看板。已有浏览器和未来 Electron 可复用本地 Web 客户端与 loopback 服务；当前未实现 Electron 容器。

DSH 插件可消费同一 Web 页面。默认禁止页面被嵌入；只有服务模式显式传 `--embed-origin <DSH Web 宿主的完整 HTTP(S) origin>` 时，CSP 才允许该单一 origin 作为祖先。禁止路径、通配符、凭据和 CSP 片段；不开放 CORS，不改变 loopback 监听、Host 校验及审批的同源/CSRF 校验。该参数只允许受信任的页面承载看板，不会加载 DSH 插件代码，也不代表插件服务已就绪。远程 DSH 的 loopback 必须从客户端可达，不能把宿主机器的 127.0.0.1 当作用户设备的地址。

客户端只操作自身 URL 和 DOM，不访问父页面或依赖桌面桥接。任务加载、筛选、详情及自动刷新可以在独立浏览器和被允许的 iframe 中复用；DSH 实际插件包、共享 runtime 和公共事件/结果协议由兼容性工作单独集成验收。
